## 1. 修改目标与动机

当前论文的模型实验只使用 MassSpecGym。MassSpecGym 规模较大且使用严格的
structure-disjoint split，但单一数据集不足以直接支持跨数据集泛化。本文计划新增
NPLIB1/CANOPUS retrieval 数据，验证固定候选池内的监督式 residual reranking 是否能在第二套
数据协议中复现，并明确区分以下问题：

1. 在 NPLIB1 自身划分上重新训练 alignment 与 reranker 时，Base、Pointwise 和 Relative 的关系；
2. MassSpecGym 训练所得模型在去重后的 NPLIB1 上能否零样本迁移；
3. 观察到的变化来自候选 coverage、基础检索器还是第二阶段列表重排。

成功标准不是获得预设的正向结果，而是形成一套可复核、无正例 forcing、身份与候选协议明确的
第二数据集证据，并据真实结果收紧或增强论文结论。

## 4. 具体内容设计

### 4.1 数据与身份协议

冻结官方 NPLIB1/CANOPUS 发布版本、下载来源和文件 SHA-256。数据处理不得原地修改原始
`data_dict`。分子身份统一使用二维 InChIKey；规范 SMILES 只用于交叉核验。候选列表保留官方
来源、原始顺序和缺失状态，任何候选过滤与 top-K 截断均写入 metadata。

官方 `split.pkl` 的源级审计发现 train/validation 共享 74 个完整及二维 InChIKey，只有 test
与二者身份不重叠。用户于 2026-09-05 确认采用以下冻结规则：从 validation 移除这 74 个身份，
train 与 test 保持不变。论文和工件必须称其为基于官方 split 派生的 de-overlapped validation，
不得称为原样官方 structure-disjoint split；处理 manifest 必须同时记录原始和派生划分统计。

对 NPLIB1 与 MassSpecGym 的 train/val/test 分别统计：二维 InChIKey 交集、规范 SMILES 交集、
谱峰精确签名重复和可行时的结构近邻分布。零样本外部测试至少移除与 MassSpecGym 训练集二维
身份重叠的 query；若近重复或结构重叠足以改变结论范围，则暂停论文结论升级并记录为
`已偏离待确认`。

### 4.2 候选与 no-forcing 协议

NPLIB1 原始 `cand_dict_large` 仅作为 test supplied-candidate retrieval，不混称 MassSpecGym
`mass` 或 `formula`。源级审计确认 `cand_dict_train_updated` 是 JESTR 正则化负池：虽覆盖
train/val，但 7,127 个 query 的精确真值 coverage 为 0%，不得与 test retrieval 候选合并或用
forcing 补成 reranker 训练集。候选中不存在真值时保留 query 并记录 coverage miss；训练 loss
只使用自然有标签 query，所有评价 query 进入 coverage-aware 指标。若为计算预算取 Base
top-256，再对 coarse top-40 使用 relative 分支，必须保存 pre-top-K coverage upper bound。

用户于 2026-09-05 确认替代方案：从已冻结的官方 `mol_dict.pkl` 分子库按分子式为
train/val/test 一致地重建 formula-conditioned 候选。真值必须作为该固定库的自然成员，不能
逐 query 插入；候选生成需记录库哈希、分子式算法、无效分子、候选规模和自然正例 coverage，
并与官方 test supplied candidates 分开命名、分表评价。若自然 coverage 不足以训练或评价，
再次设为 `已偏离待确认`，不得回退到 forcing。

### 4.3 模型实验

按已确认的重建全 split 候选协议，正式比较固定为 Base cosine、无 rank Pointwise 和无 rank
Relative。最低正式矩阵为：

- NPLIB1 in-domain：alignment seeds 42--44；每个 alignment 下 reranker seeds 42--44；
- NPLIB1 zero-shot：使用冻结的 MassSpecGym alignment/reranker checkpoint，在去重后的 NPLIB1
  test 上评价；若 checkpoint 输入协议不兼容，则报告不可比较原因而不伪造迁移结果；
- 指标：R@1、R@5、R@10、R@20、MRR、候选 coverage、Base top-K upper bound；
- 统计：按 alignment 分层的均值/样本标准差和配对差值；不把 3 个 seed 当作显著性检验。

NPLIB1 不重复 MassSpecGym 的全部 30-run 机制消融，除非主比较暴露出必须解释的新机制问题。

### 4.4 论文写法与结论门槛

- 若两个学习式模型在 NPLIB1 的预注册主指标上稳定改善各自 Base，可将主张扩展为“在
  MassSpecGym 与 NPLIB1 两套固定候选协议中均观察到监督式第二阶段重排序收益”。
- 若只在部分 checkpoint、候选 coverage 区间或模型上改善，则论文报告数据集依赖并保持窄主张。
- Relative 只有在预注册配对中相对 Pointwise 呈一致方向且证据充分时才能升级其独立收益主张；
  否则继续作为有形式性质但经验优势未建立的机制。
- 零样本迁移与 in-domain 重训必须分表，不能混合汇总。

## 8. 风险、证据边界与待确认事项

- NPLIB1 来自 GNPS，可能与 MassSpecGym 存在大规模来源、分子或谱图重叠；必须量化后才能使用“外部”或“跨数据集”。
- NPLIB1 原始候选可能天然包含真值或由 target-conditioned 数据库构造；必须区分 supplied-pool membership 与训练/截断 forcing。
- 官方 NPLIB1 train/validation 共享 74 个二维身份；未经显式去泄漏的 validation 不能用于模型选择或论文结果。
- 两数据集的离子模式、adduct、峰预处理和身份规则可能不一致；不兼容时应报告 domain/protocol shift。
- 用户指定的仓库外数据卷当前约有 2.5 TiB 可用空间；下载和中间 cache 仍需记录体积并避免无依据的重复副本。
- 当前受限运行环境内未暴露 CUDA；正式 GPU 训练前需核对宿主 GPU 与 detached `tmux` 环境。
- 若数据许可、下载工件、去重后样本量、候选 coverage 或协议兼容性不足以支持预注册矩阵，暂停论文修改并将状态设为 `已偏离待确认`，不得用较弱实验替代后宣称目标完成。
