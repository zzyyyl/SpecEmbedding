## 1. 修改目标与动机

本计划针对 2026-08-23 导师意见的六项要求，目标是把论文的创新主张、实验设计和可复现材料统一到同一组证据上：

1. 重新决定并明确论文核心贡献，依据扩展实验判断 relative candidate interaction 是否具有独立收益；
2. 在多个独立 alignment checkpoint 上重复 pointwise 与 relative reranker，降低单一 alignment checkpoint 带来的结论不确定性；
3. 完成 pointwise、directed pair、antisymmetric pair、去 spectrum conditioning、去 `L_pair`、去 `L_spec` 等机制消融；
4. 在相同候选池、身份规则和评价入口下至少复现一个公开代表性 baseline。优先复现 JESTR 的 joint-embedding cosine ranking；GLMR 保留为生成式外部方法背景，不在无法取得其完整训练/生成环境时伪造复现；
5. 发布训练 checkpoint、配置、candidate cache 索引/元数据、预测/排名输出、日志、分析脚本和对应 commit，使主结果可追溯；
6. 将重复的 closed-set、no-positive-forcing、alignment scope、SOTA 边界等内容集中到实验设置、Limitations 和 Appendix，正文篇幅用于实验分析。

本计划接受结果可能不支持 relative 优于 pointwise；若扩展实验仍不支持，论文将明确定位为 supervised second-stage reranking 及 candidate interaction 边界研究，而不是宣称 relative 模块具有稳定的独立优势。

## 2. 当前证据与问题定位

### 2.1 已有证据

- 当前论文主结果已显示 pointwise 在主要 R@1/MRR 汇总上略高于 relative；因此不能预先承诺 relative 的优越性。
- `params.yaml` 当前 canonical 设置为最多 256 个候选、relative coarse top-40、无 rank embedding、无训练期 positive forcing，且已支持 `pair_mode=antisymmetric`。
- `SpecEmbedding/utils/rerank.py` 已支持 `pair_mode=directed/antisymmetric`，但 directed 结果尚未进入主实验表。
- `analysis/transfer2026_alignment_multiseed/` 已有 alignment seed 42/43/44 的 pointwise/旧 transformer 交叉 alignment 工件，但尚未形成 current relative-vs-pointwise 的统一主矩阵。
- `analysis/transfer2026_core_ablations/` 已有部分 canonical alignment seed 42 的组件消融；需核实其协议、模型配置和本轮 `pair_mode`/loss 定义，并补齐导师指定的消融。
- `analysis/transfer2026_scholargpt_review/` 已有 difficulty、candidate cutoff、efficiency 和 query-level exporter，但本轮应把可用于论文的结果与未用于论文的审计材料分开。
- 当前代码会把 `data_summary` 写入 reranker checkpoint；本轮将扩展为完整实验元数据和可追溯 manifest。

### 2.2 外部方法核验

- JESTR 的论文说明其核心评价是谱图和分子联合空间中的 cosine similarity 排名，并公开了训练和 MassSpecGym 权重/代码；官方仓库 README 说明了训练、ranking 入口和 MassSpecGym 数据入口。
- GLMR 的 AAAI-26 页面说明其是“预检索候选 + 条件生成 + 分子相似度重排”的生成式两阶段方法。它不是本文 closed-set non-generative reranker 的同协议直接替代物；除非能够取得完整公开代码、权重和依赖，否则不声称复现。

## 4. 具体内容设计

### 4.1 核心贡献与主叙事

实验前不锁定结果方向。实验完成后按以下决策规则写作：

- 若 relative 相对 capacity-matched pointwise 在两个 candidate protocol、多个 alignment seed 和 reranker seeds 上均稳定改善，则主贡献可表述为 spectrum-conditioned candidate interaction；
- 若 relative 没有稳定独立优势，则贡献改为：固定 cross-modal candidate pool 内的 supervised residual reranking、pointwise 与 relative 的机制对照，以及 candidate interaction 的适用边界；
- 无论哪种结果，保留 closed-library、formula-conditioned、saved-embedding、no-forcing 和 fixed-pool 边界，不声称 SOTA、统计显著性或完整端到端稳定性，除非本轮确实新增相应设计和统计证据。

### 4.2 Alignment stability 实验

- 使用独立 alignment checkpoint seeds 42、43、44；记录 alignment checkpoint 的 source commit、参数哈希、训练日志和 checkpoint SHA-256。
- 每个 alignment checkpoint、candidate protocol（mass/formula）、reranker model（pointwise/relative）和 reranker seed（42/43/44）形成配对运行。
- 使用相同 train/validation/test cache 语义：训练可记录是否 force positive；验证/测试统一 no positive forcing，正例缺失记为 coverage miss。
- 将训练 query 数从当前 5,000 提升到可核验的扩大规模；优先使用完整可用 labeled training split，若硬件/时间导致资源上限，则记录实际 query 数、停止原因和敏感性分层，不隐瞒规模限制。
- 输出每个 alignment seed 的 R@1/R@5/R@10/R@20、MRR、coverage upper bound、rerank-minus-base paired deltas，以及跨 alignment 的均值、标准差和方向计数。结果只称 descriptive multi-checkpoint stability，不能自动称 confidence interval 或 significance。

### 4.3 Relative module 消融

在 canonical alignment seed 42 上先完成全矩阵，在资源允许时将关键三组扩展到 seeds 43/44：

| 变体 | 目的 |
|---|---|
| capacity-matched pointwise | 判断 supervised absolute scoring 是否已解释收益 |
| relative + `pair_mode=directed` | 判断有向 pair aggregation 与反对称约束的差异 |
| relative + `pair_mode=antisymmetric` | 当前主 relative 机制 |
| no spectrum conditioning | 判断 relative branch 是否依赖 query spectrum |
| no `L_pair` | 判断 pairwise ranking loss 的贡献 |
| no `L_spec` | 判断 mismatched-spectrum dependency loss 的贡献 |

所有变体固定 candidate pool、alignment checkpoint、train query policy、hidden width、训练轮数和 reranker seeds；报告参数量和配置差异。若某个 loss 在当前训练入口没有独立开关，先增加显式配置和测试，再运行实验。

### 4.4 统一协议 baseline

- 首选 JESTR：以官方公开实现和论文定义为依据，使用相同 MassSpecGym candidate pool、同一二维 InChIKey identity rule、相同 test query 子集和同一评价函数；明确区分“官方 JESTR checkpoint/代码运行”和“JESTR-style cosine control”。
- 若官方 JESTR MassSpecGym 权重可以在当前数据/依赖中运行，保存原始运行命令、权重来源、commit/版本和输出；若不能运行，实施仓库内可重现的 JESTR-style spectrum–molecule cosine baseline，并在论文中准确标注为 reimplemented control，不称为官方 JESTR reproduction。
- GLMR 只做公开资料和协议差异说明；若其完整代码/权重在执行阶段可获得且不扩大实验范围，再另行记录为 optional reproduction，否则保留 reported-only。
- baseline 表必须单独列出 `local reproduced`、`reimplemented control`、`reported-only` 三种状态，禁止混合排序。

### 4.5 Hard-query 与候选规模分析

- 按 base rank 区间、coverage 状态和 reranker 是否改变 top-1 划分 hard-query；报告样本数、base 与各模型的 R@1/MRR，不从少量 case 推断化学因果。
- 在固定保存的 full-pool cache 上评估 (K_r) 或 candidate cutoff（至少 40、80、128、256），同时报告 coverage upper bound、R@1/R@20/MRR 和固定硬件 forward-only 计算量；将计算量称为实现级 benchmark，不称部署 latency。
- 主文只放最能回答机制问题的表/图，其余细节移至 Appendix 和复现索引。

### 4.6 可复现材料

每个主结果行至少关联：

- alignment checkpoint 和 reranker checkpoint；
- resolved config、model config、data summary、candidate/cache protocol；
- train/validation/test 日志；
- prediction/ranking 输出及 query-level case exporter 输出；
- 运行时 Python/package/GPU 摘要；
- source commit、脚本路径、文件大小和 SHA-256。

补充材料不承诺字节级复现，但应使读者能够定位 Table 2 每一行的原始 checkpoint、配置、日志和输出。

- 正文：问题定义、方法、统一协议、主结果、alignment stability、relative 消融、baseline 对照和主要失败模式。
- Limitations：集中说明 closed-set、formula-conditioned、saved embeddings、candidate coverage、外部 baseline 复现边界和统计范围。
- Appendix：完整配置、所有 seed 表、loss 消融、hard-query 分层、(K_r)/候选规模、复现 artifact 索引和附加案例。

## 6. 实验与计算边界

- 是否新增训练实验：是。新增 alignment checkpoint 交叉重复、pointwise/relative/directed/消融和至少一个 baseline 运行。
- 是否新增评价运行：是。新增统一协议 test evaluation、hard-query、候选规模和 baseline evaluation。
- 是否进行静态数据统计：是。统计 query coverage、base rank 分层、candidate cutoff 和 artifact 元数据；这些统计与模型精度结果分开标注。
- 是否只修改文字、公式或引用：否。
- 资源策略：优先复用已有 alignment checkpoint 和 cache；新增运行目录必须使用明确的实验名、seed 和协议后缀，不覆盖正式工件。长任务使用 detached `tmux`，每阶段完成后先汇总验证再提交推送。
