## 1. 修改目标与动机

核验 `2026-08-23-ChatGPT导师修改意见.md` 中的事实判断和方法建议，修正当前稿件中可能混淆的指标、候选截断和方法定位，并根据正式审计结果决定论文走向：

1. 若 relative 在统一、干净且预先规定的协议下显示独立、稳定且有可解释的收益，继续以 relative 方法为主线；
2. 若 relative 仍不能超过容量匹配的 pointwise，诚实地将论文重构为固定候选池内的监督式二阶段 reranking framework，把 relative 降为探索性机制或负结果分析。

“让 relative 超过 pointwise”不是预设结论，也不是允许反复查看测试集后调参的验收条件。验收对象是证据是否足以支持相应主张。

## 2. 当前证据与问题定位

### 2.1 已核验的代码和论文事实

- `prepare_rerank_cache.py` 用 base score 的 top-$K$ 保存候选；`SpecEmbedding/data/datasets_rerank.py` 的 `max_candidates` 默认选择前 $K$ 个候选，正例不在其中时将 label 设为缺失，不执行 forcing。
- `eval_rerank.py` 在截断后的候选张量上重新执行模型前向和 `rank_from_scores`。因此，正文把同一组数写成 “R@1-at-K”，不能仅凭代码视为正确；必须区分“完整池上的 Recall@$K$”与“先截到 base top-$K$ 后重新排序的 top-1”。
- `RelativeCandidateReranker` 当前使用冻结的 spectrum/molecule embedding、交互特征和 base score；关系分支在 coarse top-40 上运行，具有候选置换等变性和 pair antisymmetry，但不读取 raw peaks、precursor mass、formula 或采集元数据。
- 当前 `spectrum_dependency_loss` 使用 batch 内循环错配 spectrum；代码没有证明错配样本在 precursor mass、adduct、instrument、collision energy 或候选难度上匹配。
- 当前 pilot 使用 5,000 个训练 query、三个 epoch、同一个 pre-overlap-clean alignment checkpoint 和三个 reranker seeds。官方兼容三 seed 汇总中，pointwise 在两个候选池的主要 R@1/MRR 上略高于 relative。
- 当前主表和正文明确承认 relative 尚未显示独立普遍收益，但正文 Table 1 的 “Optional candidate self-attention” 与当前正式方法不一致，应直接修正。
- 当前 bootstrap 主要比较 relative 与 base，尚未以 relative--pointwise 为主要直接比较对象；三次 reranker seed 也不等于三次 alignment replicate。

### 2.2 对导师意见的合理性判断

| 意见 | 判断 | 处理原则 |
|---|---|---|
| 先审计 R@1-at-K、截断、mask、scatter-back、身份映射 | 合理，属于 P0 | 完成逐 query 可追溯输出和单元测试后再扩展实验 |
| 修正 Table 1 的 candidate self-attention 表述和术语 | 合理，属于低风险必修 | 与指标审计同一轮修订，中英文同步 |
| 直接比较 relative 与 pointwise，并区分 seed 层级 | 合理，属于 P1 | 报告 paired effect、query bootstrap 和 seed dispersion，不把任一单独统计量写成端到端显著性 |
| 使用 overlap-clean 主协议重训 alignment、重建 cache | 方法学上合理，但有计算成本 | 作为正式主结果候选；若无法完成，保留 pilot 为明确标注的 pre-overlap-clean 证据，不称为 clean canonical |
| 5k/20k/50k/100k/全量学习曲线和 3×3 seeds | 对方法论文有价值，但不是审计前置条件 | 审计通过且选择 relative 主线后执行；资源不足时缩减并记录理由 |
| confidence gating、hard-pair loss、hard spectrum mismatch | 是合理的待验证假设，不是已知修复 | 每项独立消融、固定验证选择规则；不得预先声称一定改善 |
| raw peaks、前体质量、公式、图差异和 predicted fragments | 质疑合理，但属于新方法和新数据协议 | 不与现有 embedding-only 主线混改；只有明确扩大范围后才建新分支和新 baseline |
| RankNet/ListNet/LambdaMART/DeepSets/Set Transformer 全部加入 | 方向合理但范围过宽 | 先保留容量匹配 pointwise、当前 relative、loss/conditioning 消融和一个集合模型；外部方法不能以未经复现的数值代替 |
| 为每个 $K_r$ 重新训练 | 若要声称 $K_r$ 敏感性则合理 | 明确区分候选池截断 $K$ 与关系分支深度 $K_r$；evaluation-only 截断不能冒充 $K_r$ 重训 |
| 发布完整数据、checkpoint 和全部日志 | 可复现性要求合理，但受许可证和匿名化限制 | 采用分层发布：优先发布逐 query 排名/得分、配置、hash、表格生成脚本和 bootstrap 输入；受限工件不承诺公开 |
| 先重写整篇论文再补实验 | 不采纳 | 先完成审计和正式实验，再决定标题、摘要、贡献和正文结构 |

特别注意：同分子式不自动等于负样本；hard negative 必须依据 2D identity 标签排除身份等价正例。当前方法不使用 raw peaks 也不自动意味着方法无 MS/MS 特异性，需把“embedding 提供的谱图条件”与“显式峰证据”分开陈述。

## 4. 具体内容设计

### 4.1 阶段一：指标和实现审计（P0，先于模型修改）

建立一套人工可读的逐 query 输出，至少包含：

```text
query_id, positive_identity, candidate_count,
base_rank, coarse_rank, relative_rank, pointwise_rank,
candidate_order_hash, positive_present,
base_hit@1, rerank_hit@1, rerank_hit@5, rerank_hit@20, rerank_hit@40
```

候选 ID 在公开产物中使用匿名稳定标识；内部审计可保留原始索引。对每个 $K$ 同时计算并分开命名：

1. 完整候选池模型分数下的 Recall@$k$；
2. 先按 base top-$K$ 截断、再在截断池前向排序的 top-1/Recall@$k$；
3. 候选覆盖上界 $U_K$、positive missing 数量和所有 query 的分母。

用人工构造的小 cache 覆盖正例位于 1、2、5、20、40、80、缺失和多 identity-positive 的情况，并验证：

- base 排序、截断、label 更新和 no-forcing；
- padding/mask、top-$K_r$ scatter-back 和候选顺序置换；
- pair antisymmetry 及 relation branch 对非候选 padding 的不敏感性；
- 无正例 query 不进入训练 loss、但进入评价分母；
- full-pool Recall@$K$ 不被误标为截断后 R@1。

若审计发现实现错误，暂停后续扩大实验，先修复代码、补回归测试并重算受影响工件。若代码正确但正文指标名称错误，只修正文、分析脚本和结果 manifest，并保留原始数值来源。

### 4.2 阶段二：正式协议与主线分流

先固定以下 protocol manifest：

- MassSpecGym structure-disjoint split；
- mass/formula 候选协议及其 formula-conditioned 限定；
- official JSON candidate order、2D InChIKey identity 和 saved-embedding 范围；
- natural candidate、无 positive forcing、$K=256$ 和 relation $K_r=40$ 的当前基线；
- overlap-clean 与 pre-overlap-clean 的 checkpoint、cache、query 数和 hash；
- validation 选择规则、alignment seed、reranker seed 和训练规模。

随后对现有 relative 与 pointwise 做直接的逐 query paired 比较，至少报告 R@1、MRR、95% bootstrap CI、relative-only correct、pointwise-only correct、both-correct 和 both-wrong。query bootstrap 只描述固定 checkpoint/seed 下的 query uncertainty；alignment 和 reranker seed 变化另行报告。

以验证集预先定义分流：

- 若 relative 相对 pointwise 的方向、大小和机制分析在 clean protocol 下具有一致支持，进入 4.3A；
- 若差异接近零、方向不稳定或主要依赖单一 seed，进入 4.3B，把 relative 定位为探索性机制，不继续以测试集结果驱动改模。

### 4.3 阶段三：方法实验（仅在阶段二允许后执行）

#### 4.3A relative 主线候选

按独立变体实施，先在训练/验证集确定配置，再锁定测试运行：

1. **confidence gating**：由 coarse top-1/top-2 margin、候选分布不确定性等构造 $eta(s,C)$，比较无 gate、固定 gate 和可学习 gate；报告 easy/hard 分层，不假定 gate 必然改善。
2. **hard-pair relation supervision**：只在自然存在正例的训练 query 中，从 coarse scorer 挖掘与正例相近的负例；同分子式、指纹相似或 embedding 相近只能作为候选条件，不能绕过 identity-positive 排除。直接 pair loss 的目标、权重和 hard-negative 数量写入 manifest。
3. **spectrum mismatch audit**：先统计现有 cyclic mismatch 是否与原 query 在分子身份、precursor mass、adduct、instrument、collision energy、候选池类型和难度上混杂；若元数据可用，再实现条件匹配 mismatch，并对 replicate spectra 做排除审计。元数据不足时只报告限制，不声称完成了 hard mismatch。
4. **领域证据分支（可选）**：只有在明确扩大数据/输入范围后，才研究 raw peak cross-attention、候选图差异或 fragment evidence；该分支必须与 embedding-only 主线分表，并有相同容量/输入控制。

#### 4.3B framework 主线候选

保留当前 relative 的等变性、反对称性和分层负结果，把 pointwise 作为主要有效控制；relative、gate 或 relation-loss 变体作为探索性分析。正文不再暗示候选关系已经被证明优于 pointwise，标题和摘要改为监督式二阶段 reranking framework。

### 4.4 阶段四：正式实验矩阵

在资源允许且阶段二通过后，优先级如下：

1. overlap-clean alignment seeds 42/43/44 × 每个 alignment 的 reranker seeds 42/43/44；若复用既有 alignment 工件，必须确认其训练协议与当前 no-forcing 主线一致。
2. 训练规模学习曲线：5k、20k、50k、100k、全量；至少报告 relative、pointwise 及差值，记录 early stopping 和收敛曲线。若计算预算不足，选择一个预先固定的大规模子集并记录理由。
3. 关系深度 $K_r=10,20,40,80$ 的独立训练；另行报告候选池截断 $K$，不得用 evaluation-only 截断代替 $K_r$ 重训。
4. 受控 baseline/ablation：capacity-matched pointwise、当前 relative、listwise-only、pairwise-only、无 spectrum conditioning、无 molecular relation，以及一个明确实现的集合模型。RankNet/ListNet 作为 loss 对照，Set Transformer/DeepSets 作为模型对照；不无边界扩展到所有建议模型。
5. overlap-clean 主结果及删除 3 个 test-overlap query 的敏感性；测试集删除只作敏感性，不替换正式全测试分母，除非 venue 或协议明确要求。
6. query-level mechanism cases、base-rank/easy-hard 分层和固定硬件下 measured efficiency；只有实际测量后才报告 latency、吞吐或显存。

统计报告必须同时包含候选池、alignment checkpoint、alignment seed、reranker seed、训练规模、$K$/$K_r$、identity rule 和 query 分母。

- 摘要和结论如实报告 relative--pointwise 的差值与区间；若没有稳定独立收益，明确写成 framework/negative mechanism evidence；

## 6. 实验与计算边界

- 是否新增训练实验：是；阶段四需要正式 reranker/alignment 训练，执行前确认 GPU、数据、磁盘和运行时间。
- 是否新增评价运行：是；包括指标审计、逐 query 输出、paired bootstrap/permutation、overlap-clean 敏感性和 $K$/$K_r$ 分析。
- 是否进行静态数据统计：是；包括跨 split overlap、replicate mismatch、候选身份、候选数和 query 分母审计。
- 是否只修改文字、公式或引用：否；文字修改必须后置于结果分流。
- 外部 JESTR/GLMR 继续为 reported-only，除非另行批准完整、协议匹配的复现实验。
- 任何 raw peak、metadata、候选图或 fragment 输入都会改变当前 saved-embedding 评价边界；实施前必须在计划中记录新输入、缓存、baseline 和匿名发布影响。

## 8. 风险、证据边界与待确认事项

- **指标风险**：若逐 query 审计证实正文数值来自 Recall@$K$ 而不是截断后 R@1，必须改名并重建相关表述；若实现本身错误，需重新评价全部受影响模型。
- **结论风险**：relative 可能在 clean protocol 下仍不优于 pointwise；此时停止以“超过 pointwise”为目标的继续调参，采用 framework 分流。
- **资源风险**：3×3 alignment/reranker、全量学习曲线和多个 $K_r$ 可能超出当前 GPU/时间预算；缩减实验不能隐藏，必须在结果中写明。
- **协议风险**：若 pre-overlap-clean checkpoint 不能被 clean pipeline 替代，主表必须明确其历史/试验性质，不能同时称为正式 canonical 和 pilot。
- **数据风险**：原始谱图、候选库、checkpoint 和日志可能受许可证、隐私或匿名化限制；发布计划采用可公开层级，不承诺无法交付的完整重现。
- **范围风险**：加入 raw peaks、化学元数据或 fragment evidence 会改变方法输入和论文贡献；触发时将当前计划标为 `已偏离待确认`，暂停该分支并请求确认。
- **投稿决策待确认**：目标 venue 页数限制、是否允许新增大规模实验、作者/COI、数据发布许可和 AI disclosure 由作者在执行发布阶段确认。
