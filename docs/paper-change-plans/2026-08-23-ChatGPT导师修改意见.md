# 关于《Spectrum-Conditioned Relative Reranking for MS/MS Molecule Retrieval》的修改意见

同学：

我已经认真审阅了目前这版论文。总体来看，论文选题具有一定价值，整体技术流程较完整，作者对于候选池构造、身份判定、候选顺序、训练时正样本处理、随机种子含义以及实验边界等问题也有较强的审计意识。论文提出的相对候选关系模块具有反对称性、候选排列等变性、不使用排名嵌入、训练时不强行插入正样本等特点，并设置了参数量近似匹配的 pointwise control，这些设计说明你们对实验控制问题进行了较认真地考虑。

但是，我需要明确指出：**当前稿件还没有达到一篇成熟方法论文应有的完成度。** 问题并不主要在语言表达，而在于论文提出的核心方法尚未被实验结果充分支持。接下来的修改不能停留在文字润色、补充限制说明或者继续扩展审计内容上，而应围绕“方法是否真正有效、为什么有效、在什么条件下有效”进行实质性重构。

## 一、首先要重新明确论文的核心贡献

目前论文的标题、摘要和方法部分都将“spectrum-conditioned relative candidate relations”作为核心创新，但主实验显示，在 Mass 和 Formula 两种候选池上，容量匹配的 pointwise model 在主要的 R@1 和 MRR 指标上均略高于 relative model：

* Mass：pointwise R@1 为 51.37%，relative 为 50.98%；pointwise MRR 为 59.03%，relative 为 58.71%；
* Formula：pointwise R@1 为 66.65%，relative 为 66.32%；pointwise MRR 为 71.66%，relative 为 71.29%。

论文结论也已经承认，现有结果只能支持监督式二阶段重排整体有效，尚不能证明相对关系模块具有独立且稳定的收益。

因此，当前稿件存在明显的“方法贡献与实验证据错位”：

> 论文提出并重点讨论的是 relative reranking，但主实验真正证明的是 pointwise supervised reranking 的有效性。

既然你们希望将论文定位为方法论文，而不是一篇实验审计或负结果报告，那么下一版必须优先解决这一矛盾。具体而言，有两条路线：

第一条，也是我更建议采用的路线，是继续保留 relative reranking 作为核心方法，但需要对其进行实质性改造，并通过完整实验稳定地超过容量匹配的 pointwise baseline。

第二条路线是承认 relative module 未带来稳定收益，将论文重构为一个更一般的监督式二阶段 reranking framework，并把 relative module 降为探索性机制或负结果分析。但这样一来，标题、摘要、方法贡献和论文叙事都需要重新设计，且方法创新性会进一步减弱。

从方法论文的目标出发，我建议优先选择第一条路线。

## 二、相对关系模块需要进行实质性修改

### 1. 解决“困难样本获益、容易样本退化”的问题

现有分层结果已经提供了一个非常重要的线索：relative model 的收益主要集中在 base rank 为 2–5 或 6–20 的困难查询上，而对于 base rank 已经为 1，或者 base top-1 similarity 较高的查询，相对重排反而造成明显性能下降。

这说明当前相对模块不是完全无效，而是被无条件地应用在所有查询上，导致它在困难查询上纠正排序的同时，也破坏了原本已经正确的容易查询。

下一版应优先考虑加入**查询级置信度门控机制**。例如，将最终得分修改为：

[
q_i=c_i+\eta(s,C)\beta r_i,
]

其中 (\eta(s,C)) 是由当前候选集不确定性决定的门控系数。门控输入可以包括：

* coarse top-1 与 top-2 的得分间隔；
* 候选得分分布的熵；
* base score 与 coarse score 的一致程度；
* top-(K) 候选得分方差；
* 当前查询的候选池规模；
* spectrum embedding 与 top candidates 的整体匹配置信度。

当 pointwise branch 已经具有较高置信度时，应降低甚至关闭 relative branch；只有在候选之间难以区分时，才启用相对关系推理。这样的方法设计能够直接回应现有实验中“难例获益、易例受损”的现象，也比继续增加普通 MLP 层更具有针对性。

### 2. 对相对偏好进行直接监督

目前相对偏好 (p_{ij}) 主要通过最终排序损失间接学习。由于 absolute branch 已具有较强表达能力，相对关系分支很可能被 absolute branch 吸收，或者退化为一个成本较高但贡献有限的附加项。

建议增加直接针对正样本与困难负样本的 relation loss，例如要求：

[
p_{+j}>\gamma,\qquad j\in H,
]

其中 (H) 为由 coarse scorer 挖掘出的 hard negatives。训练时不应平均处理所有负样本，而应重点选择：

* 与正样本 base score 接近的候选；
* 与正样本图嵌入相似的候选；
* 与正样本具有相同分子式的候选；
* 分子指纹相似但结构不同的候选；
* 当前 pointwise model 容易混淆的候选。

相对模块本来就应解决“两个相似候选之间如何比较”的问题。如果仍然使用大量容易负样本进行训练，相对关系信号会被稀释。

### 3. 增强方法的质谱领域特异性

当前 reranker 实际只使用冻结的 spectrum embedding、molecule embedding、embedding 交互项和 base score。论文明确说明，相对模块不直接读取 raw peaks、precursor mass、formula、adduct、instrument 或 collision energy。

这会使审稿人质疑：所谓的 spectrum-conditioned relative comparison 是否只是一个通用 embedding reranker，而不是针对 MS/MS 检索问题提出的领域方法。

下一版应考虑让 relative module 显式利用“两个候选之间的差异性谱图证据”。可行方向包括：

* 计算候选分子对之间的图结构差异表示；
* 将差异子结构与 spectrum peak tokens 进行轻量 cross-attention；
* 建模“哪些碎片支持候选 (m_i)，但不支持候选 (m_j)”；
* 引入中性丢失、分子式差异、前体质量误差等候选对特征；
* 对两个候选的 predicted fragments 或 substructure evidence 进行比较；
* 在相同分子式候选中重点学习位置异构体和结构异构体的区分证据。

方法部分最终需要回答的不是“两个 embedding 哪个更相似”，而是：

> 对于两个化学上相近的候选，当前 spectrum 中哪些证据更支持候选 A，而不是候选 B？

只有把这一点建模出来，relative module 才能形成较清楚、不可被普通 pointwise MLP 轻易替代的方法贡献。

### 4. 重新设计 spectrum-dependency loss

目前 (L_{\text{spec}}) 使用 minibatch 内循环错配 spectrum。 这种随机错配可能构成过于简单的负样本。例如，错配 spectrum 与原 spectrum 的 precursor mass、adduct 或候选池条件可能相差很大，模型只需要识别粗粒度分布差异即可满足损失，而不一定真正学习到了区分困难候选的细粒度谱图信息。

建议将随机错配改为条件匹配的 hard spectrum mismatch，至少满足：

* 来自不同分子身份；
* precursor mass 相近；
* 候选池类型相同；
* 尽可能匹配 adduct、instrument 和 collision energy；
* base-score 分布或候选难度相近。

同时需要明确检查 batch 内是否存在同一分子的 replicate spectra，避免将同分子不同谱图错误地作为负样本。

## 三、实验部分需要重新实施，而不仅是增加解释

### 1. 使用完整训练规模进行正式实验

当前新 reranker 只使用了 194,119 个训练查询中的 5,000 个，并且主要证据来自三个 epoch、三个 reranker seed 和一个 alignment checkpoint。论文本身也承认，这不构成 alignment-level 或 end-to-end stability。

这样的设置适合作为 pilot，但不足以作为方法论文的正式主结果。下一版至少应报告：

* 5k、20k、50k、100k 和全量训练数据的学习曲线；
* 每个规模下 relative 与 pointwise 的差值；
* 数据规模增大后 relation branch 是否表现出更明显优势；
* 训练轮数、早停位置和收敛曲线；
* 不同候选池上的训练稳定性。

如果由于计算成本无法完成全量实验，也需要选择足够大的固定子集，并说明统计功效，而不能继续把 5,000-query pilot 作为主要结论。

### 2. 区分 reranker seed 与 alignment seed

目前三次实验只改变 reranker initialization、data-loader order、candidate shuffling 和 dropout，仍然共用同一个 alignment checkpoint。

下一版应至少进行：

[
3\ \text{alignment seeds}\times 3\ \text{reranker seeds}
]

的实验设计。需要分别报告：

* alignment checkpoint 间差异；
* 同一 alignment 下的 reranker seed 方差；
* relative-minus-pointwise 的均值和置信区间；
* Mass 和 Formula 两个候选池的独立结果。

否则目前报告的标准差只能说明第二阶段训练波动较小，不能说明整个方法具有端到端稳定性。

### 3. 统计检验必须直接比较 relative 与 pointwise

当前 bootstrap 主要报告 relative-minus-base，而核心科学问题实际上是：

> relative module 是否优于容量匹配的 pointwise model？

因此，应基于逐查询预测，对 relative 与 pointwise 直接进行 paired bootstrap 或 permutation test，报告：

* R@1 差值；
* MRR 差值；
* 95% 置信区间；
* relative 改正而 pointwise 错误的查询数；
* pointwise 改正而 relative 错误的查询数；
* 两种方法同时正确和同时错误的查询数。

不能再用“relative 显著优于 base”来间接支持 relative mechanism，因为 pointwise 同样显著优于 base。

### 4. 补充真正受控的排序基线

目前主要受控基线是 absolute pointwise scorer。为了证明所提出的关系机制不是普通 learning-to-rank 损失或候选集合建模即可替代，还应加入：

* RankNet；
* ListNet 或 ListMLE；
* LambdaRank/LambdaMART 类排序目标；
* DeepSets；
* Set Transformer；
* 不含 spectrum conditioning 的 pairwise model；
* 只使用 candidate difference 的 pairwise model；
* 参数量匹配、计算量尽可能匹配的交互模型。

外部的 JESTR 和 GLMR 可以继续作为背景方法，但不能仅通过文字说明来代替数值比较。当前论文明确说明这两类方法未被复现，也未进行统一候选池、身份规则和预处理下的受控比较。

如果无法完整复现外部方法，应将“内部受控比较”和“外部公开结果比较”分成两张表，清楚说明可比性边界。

### 5. 重新训练不同 (K_r)，不要只做评估阶段截断

目前 (K_r=40) 是固定设计，而部分 (K) 分析只是对同一缓存进行 evaluation-only truncation，并非针对不同候选规模重新训练。

建议分别训练：

* (K_r=10)；
* (K_r=20)；
* (K_r=40)；
* (K_r=80)。

需要分析：

* 候选数增加后 relation branch 是否仍然有效；
* 计算复杂度与性能收益的关系；
* hard negatives 是否主要集中在 top-20；
* coarse scorer 的错误是否限制了 relative module。

否则不能根据 evaluation-only truncation 对候选规模敏感性作出方法结论。

## 四、必须进行一次完整的指标和代码审计

论文中有一处需要优先核查。Table 2 中 relative 和 pointwise 的 Mass R@20 分别为 80.49 和 80.71，R@40 分别为 86.13 和 86.03；而正文所谓的 “R@1-at-K” 在 (K=20) 和 (K=40) 时，恰好再次报告为 80.49/80.71 和 86.13/86.03。

从指标定义看，截断候选池后重新排序得到的 R@1，不应在一般情况下机械地等于原始完整候选池的 R@20 或 R@40。这里可能是：

* 指标名称写错，实际报告的是 coverage@K 或 Recall@K；
* 评估代码读取了错误字段；
* 截断后没有真正重新执行预期的排序；
* 聚合脚本将两个指标混淆。

我不能仅凭论文文本断定代码存在错误，但这个现象必须在下一版提交前彻底查清。建议增加人工可验证的单元测试，并对少量查询输出：

```text
query_id
positive_candidate_id
positive_index
base_rank
coarse_rank
relative_rank
pointwise_rank
candidate_count
hit@1
hit@5
hit@20
hit@40
```

同时，应使用手工构造的小候选集合验证：

* 正样本位于第 1、2、5、20、40、80 位时的指标；
* 截断前后正样本缺失时的处理；
* 多正样本身份规则；
* 候选顺序打乱后的等变性；
* padding 和 mask；
* top-(K_r) scatter-back；
* relative pair antisymmetry；
* 无正样本查询是否确实不进入训练损失。

在确认指标正确之前，不建议继续扩展其他实验。

## 五、数据重叠与正式实验配置需要统一

论文说明，跨 split 的 spectrum-record signature 审计发现训练集与验证集有 6 个相同记录签名，与测试集有 3 个相同记录签名，虽然目标分子不同且均被标记为 simulation challenge，但仍属于需要披露的跨 split 谱图记录重叠。

同时，论文又说明新的 no-forcing pilot 使用的是 pre-overlap-clean alignment checkpoint，而不是文中定义的 overlap-clean canonical configuration。

这一点会使正式主结果的实验协议显得不统一。下一版建议：

1. 使用 overlap-clean pipeline 重新训练 alignment model；
2. 使用该 clean checkpoint 重新生成所有 candidate caches；
3. 重新训练 relative 和 pointwise models；
4. 单独报告删除 3 个 test-overlap 查询后的敏感性结果；
5. 明确 canonical configuration，不再并列维护多个容易混淆的历史配置；
6. 将历史 pre-overlap-clean pilot 移至附录，不再作为主表结果。

方法论文的主表应来自一条清晰、统一、可复述的正式实验流水线，而不应依赖历史 checkpoint 与局部重新评估的拼接。

## 六、真实性与可复现性需要进一步加强

从论文内部表述来看，你们愿意报告不利于自身方法的结果，也主动披露了训练规模、随机种子边界、未完成的外部比较和 AI 辅助范围，这些做法是负责任的。论文还明确说明，数值结果来自所述软件流程，而不是由语言模型生成。

但是，内部披露充分并不等于外部可验证。目前匿名补充材料不包含真实数据、候选池、alignment checkpoint、reranker checkpoint、缓存、日志以及 pilot result artifacts，所提供的 synthetic smoke test 无法复现论文中的科学结果。

下一版至少应提供以下可公开产物：

* 完整配置文件；
* 每个 checkpoint 的 hash；
* 每个缓存的 hash；
* 每个 seed 的逐查询最终 rank；
* 候选 ID、target identity 和预测得分；
* 训练与验证曲线；
* early-stopping epoch；
* 评估脚本和锁定环境；
* 生成主表的原始 CSV/JSON；
* bootstrap 输入和输出；
* 所有图表的生成脚本。

如果原始 spectrum 或候选文件受许可限制，仍然可以发布不含原始谱图的逐查询排序结果和匿名化候选标识。至少要使外部研究者能够重新计算 R@1、MRR、置信区间和方法间逐查询差异。

在论文中，应将“真实性”表述为“结果来源和流程披露”，将“可复现性”表述为“外部能否实际重算结果”，两者不要混为一谈。

## 七、论文结构需要从“审计报告”转回“方法论文”

当前稿件对候选顺序、历史版本、artifact provenance、不可声称事项和旧 Transformer 边界进行了大量说明。这些内容有价值，但在正文中所占比重过高，削弱了核心方法叙事。

下一版建议按照以下结构重写。

### 1. Introduction

只围绕一个核心问题展开：

> 在 pointwise spectrum–molecule scoring 无法区分相似候选时，显式的候选相对比较能否利用差异性谱图证据改善排序？

不要在引言中花过多篇幅解释历史实验和不可复现事项。

### 2. Method

重点说明：

* pointwise branch 的功能；
* relative branch 提供了什么 pointwise branch 无法表达的证据；
* hard-pair supervision；
* confidence gating；
* spectrum-specific candidate difference；
* 计算复杂度；
* 排列等变性和反对称性的形式化证明。

目前论文虽然说明了 (p_{ij}=-p_{ji})，但 relation weight (w_{ij}) 的计算过程仍需要更完整地写出，包括网络结构、归一化方式、mask、激活函数和参数共享方式。

### 3. Experiments

正文只保留：

* 主结果；
* relative 与 pointwise 的直接统计比较；
* 多 alignment seeds；
* hard/easy query 分析；
* 关键消融；
* 效率对比。

候选顺序重建、identity audit、历史 Transformer、positive forcing 和旧 artifact provenance 应移至附录。

### 4. Mechanism Analysis

需要单独回答：

* relative module 在哪些查询上有效；
* 哪些候选关系被学习；
* easy queries 为什么退化；
* 门控后是否减少退化；
* 哪些 peaks 或 substructures 导致排序变化；
* relative 与 pointwise 的错误是否互补。

建议加入若干逐查询案例，而不只是聚合分层数字。

## 八、需要修正的具体文字与一致性问题

Table 1 将 “Ours” 的 candidate interaction 写成了 “Optional candidate self-attention”，但正式方法实际上是 antisymmetric relative pair module；candidate-set Transformer 只是历史 secondary baseline。

这一表述很可能是旧版本方案遗留，必须修正。建议改为：

> Spectrum-conditioned antisymmetric pair interaction over the coarse top-(K_r) candidate subset.

此外，还应统一以下术语：

* “official-compatible”与“official evaluation”；
* “full-pool”与“top-(K) evaluation”；
* “coverage upper bound”与“Recall@K”；
* “reranker seed”与“alignment seed”；
* “exact-SMILES identity”与“2D-InChIKey identity”；
* “historical audit”与“formal method result”；
* “R@1-at-K”与普通“R@K”。

摘要中不应只强调方法设计和实验协议，而回避 relative model 未优于 pointwise 的事实。如果主结果仍保持现状，摘要必须明确写出 pointwise 略高于 relative；如果下一版通过方法修改获得了稳定收益，则应报告 relative-minus-pointwise 的具体差值和置信区间。

最后再统一修改标题、摘要、贡献、方法描述、实验主表和结论，并将历史审计内容移至附录。

## 十、最终要求

这篇论文目前并不是没有价值。其优点在于问题定义较清楚，实验边界披露较充分，也没有刻意隐藏不利结果。但作为一篇方法论文，不能仅仅证明“增加一个监督式 reranker 比余弦排序更好”，而必须证明：

1. 为什么需要候选间相对关系；
2. 相对关系提供了什么 pointwise scoring 无法提供的信息；
3. 该机制是否在独立训练和严格统计检验下稳定有效；
4. 它是否值得额外的计算开销；
5. 它是否真正利用了 MS/MS 的领域证据，而不是只对冻结 embedding 做通用重排。

因此，我对当前版本的意见是：**进行实质性大修，不建议仅做语言层面的修改后直接投稿。**

下一版最重要的判断标准只有一个：

> 在统一、干净、可复现的实验协议下，修改后的 relative model 是否能够稳定、显著且有机制解释地优于容量匹配的 pointwise baseline。

如果能够做到这一点，论文才具备较明确的方法贡献；如果仍然不能做到，就应及时调整论文定位，不再将 relative candidate relation 作为主要创新点。

请按照“先核查正确性、再修改方法、再扩大实验、最后重写论文”的顺序推进，不要反过来先花时间继续润色摘要和讨论部分。
