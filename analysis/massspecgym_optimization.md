- 状态：2026-09-09 14:07 派发，14:12 完成 CPU 准备；14:34 完成固定 baseline 验证，

- 固定起点：v1.5 r4 alignment seed42，原按验证对比损失选中 epoch15；来源见
  [准确率排查](massspecgym_v15_regression_audit.md)。不重新执行旧 12 组矩阵。
- 假设：验证对比损失最优的 epoch 未必具有最好的候选检索排名；直接观察完整验证检索
  可以改善选优，并区分 checkpoint 选择问题与表示/训练目标问题。
- 主要改变：每个完整 epoch 后，重新编码全部 Mass 验证候选与 query，按 Top-1、MRR
  顺序选 checkpoint，同时保存 Top-1/5/10/20/MRR 的非支配候选文件和完整轨迹。
- 固定条件：seed42、随机初始化、原有两塔结构/损失/增强/AdamW/学习率/温度/batch128；
  每轮 194,119 个 train query，19,423 个有效 val query，最多 100 epochs、patience5。
  验证索引和 DataLoader 使用独立 RNG，不应额外消耗训练随机数流。
- 评价基线：使用同一验证索引，对 r4 原 checkpoint 做一次 fresh encoding；避免把旧 fp16
  exact-SMILES cache 指标直接与新 float32、二维多正例指标比较。索引保留源顺序与重复条目，
  只沿用已审计的无效图排除，所有无正例 query 保留分母。
- 同分规则：主指标对应 `torchmetrics==1.8.2` 的逐 query CPU `argsort(descending=True)`，
  padding 先移除；稳定排序另存敏感性视图。MRR 按同一排名扩展，不声称它是官方已报告指标。
- 资源：单卡显式 CUDA，物理 GPU 0/1 择一等待；分子编码 batch512、谱图 batch128、CPU workers4。
  新验证索引实测 827,600 个唯一分子、19,423 个 query，全部 query 自然包含正例；
  记录 6 个源候选图排除条目，没有多正例 query。逐轮记录验证耗时，
  先实测再决定是否需要图缓存；不为省时减少 query 或候选。
- 队列阶段：导入已审计数据 → CPU 验证索引 → 固定 checkpoint 验证 → 单 seed alignment。
  该队列不包含 test 推理或 reranker，完成只表示 A01 候选完成。
- 保留规则：依据完整验证 Top-k/MRR 的改善和代价决定是否成为新 incumbent；若只有选优
  改善而表示能力仍不足，下一项按计划考虑参数、预训练来源及候选对比目标，不转向 test 调参。
  A01 完成后还要比较其自身轨迹的验证 loss 最低轮与检索最优轮：r4 与 A01 的早期逐轮 loss
  已观察到差异，相同 seed/超参数不代表逐位相同的训练轨迹，不能把跨运行差异全部归因于选优规则。

## A02 准备：质量邻近分组的全量 batch

- 状态：实现 `fc42b27`、测试、完整 CPU 顺序核验及真实输入 dry-run 通过；
  等待 A01 完整验证轨迹后决定是否派发，未启动第二轮训练。
- 假设：随机 in-batch 负例很少要求区分相近质量结构，训练判别任务与自然候选检索存在差距。
  完整 train 元数据的超几何期望显示，batch128 中约 3.10% 的 query 遇到 10 ppm 内的
  不同二维身份负例，batch512 约 10.42%；10 ppm 是诊断阈值，并非源候选成员资格的完整复现。
  精确数值、短尾批处理和可重跑脚本见外部 `alignment_inputs_20260909` 审计。
- 唯一改动：训练 batch 的组装顺序。按训练分子的计算精确质量排序，质量同分时随机打乱，
  循环平移后形成 32-query 小组，再随机组合 4 组为 batch128；尾部完整保留。
  每个 epoch 使用独立确定的 seed，全部 194,119 条 query 恰好出现一次。
  小组内提供邻近质量比较，小组间提供更广泛的负例；保存每轮质量/顺序 SHA-256 与唯一覆盖数，
  训练完成审计核对实际 batching 与预检配置。
- 固定：A01 的模型、初始化、loss、batch128、优化器、学习率、增强、验证检索与选优规则。
  不使用验证/测试标签组 batch，不改变评价候选，也不增加每步编码的分子数。
- 限制：相近质量不等于困难负例或源候选身份；该方法不保证性能提升，仍须完成实际训练验证。
  若效果不足，再考虑自然候选对比目标和经过来源审计的预训练；不把 sampler 检查写成模型结果。

## D01：固定 baseline 的完整验证错误诊断

2026-09-09 对 A01 前置 r4 baseline 的已完成 float32 分数进行 CPU 分析，覆盖全部 19,423 个
有效验证 query。独立按源候选顺序和既定 CPU argsort 重算排名，逐条与保存排名一致，
Top-k/MRR 与原回执一致；没有重新推理、训练、过滤候选或修改元数据。
输入/脚本/逐 query 输出哈希与依赖版本见计划第 10 节的 `validation_errors_20260909` 回执。

| 原始 adduct 分组 | query 数 | Top-1 (%) | Top-10 (%) | MRR |
| --- | ---: | ---: | ---: | ---: |
| [M+H]+ | 14686 | 5.8151 | 30.5801 | 0.137715 |
| [M+Na]+ | 4737 | 4.1165 | 36.1621 | 0.148056 |

- 钠加合物的 Top-1 较低，但 Top-5/10/20 与 MRR 更高；这些是受结构、仪器和谱图分布等因素
  共同影响的描述性分组，不能推出加入 adduct 特征的因果收益，也不能把它作为低准确率的唯一原因。
- 错误 Top-1 中 39.15% 与真值同分子式。这支持继续检查结构判别能力，但不证明具体损失或结构
  改动必然有效；真值分子式仅用于事后错误分类，没有送入 Mass 模型或重排器。
- 仅从实测 `precursor_mz`、记录的 adduct 和固定版本 matchms 加合物表推导中性质量，忽略
  来源可能不清的 `parent_mass`；没有使用目标结构来修复输入。真值质量误差中位数为 0.148 ppm，
  804 个 query（4.14%）超过 10 ppm，最大约 1824 ppm。直接追加 10 ppm 硬过滤会损失这些真值，
  因而不实施该过滤。未来若试质量一致性特征，应保留完整候选并使用可处理异常值的软打分。
- 仪器/碰撞能量缺失的 query 同样保留于总体与分组分母；详细分组在原始回执，不据这些分组
  改变训练/验证排除规则。当前诊断不替代官方候选生成协议，也不外推为 test 表现。

决策：维持 A01 的原定训练与选优规则；A02 仍只改变 batch 组成，待 A01 完成后决策派发。
元数据分支和软质量特征保留为后续假设，暂不同时加入本轮，也不据静态诊断宣布性能改善。
